## Verified as correct (no changes)

- **Coverage math**: `howMuchGravel.ts`'s 12×50×4in → ~7.4 yd³ / ~10-11 tons, and 100×12×4in → ~15 yd³ / ~20-22 tons, both check out against `quantityForArea`/`tonsPerYard` (1.4 for gravel in both metros).
- **Crusher run vs #57 compaction (85-95% vs 70-80% of loose volume)**: corroborated by multiple independent industry sources (Aggregate Markets, Hello Gravel, Smoky Mountain Sand & Gravel, Komplet America) — matches exactly across `bestGravel.ts`, `crusherRunVs57VsFlexBase.ts`, and the `BestGravel.tsx`/`CrusherRunVs57VsFlexBase.tsx` comparison tables.
- **Depth/layer build (4-6in base + optional 2-4in middle + 2-3in top = 6-9in / up to 13in total)**: consistent across `depthAndLayers.ts`, `installationSteps.ts`, `gravelParkingPadRvPad.ts`, and their page components.
- **Asphalt/concrete lifespans (asphalt 15-20yr resurface / 20-30yr replace; concrete 30-40yr)**: matches current Angi/industry sources; consistent across `gravelVsAsphaltCost.ts` and `howLongGravelDrivewayLasts.ts`.
- **Truck fleet capacities** (~7 / 14-15 / 24-28 tons small/medium/large) in `TruckloadCoverageAndDeliveryMinimums.tsx`'s table: correctly spans both metros' actual truck configs (LI: 7/14/28t, DFW: 7/15/24t).
- **No hardcoded prices** elsewhere: grepped every content module and every `pages/guides/*.tsx` for `\$[0-9]`; only the cost.ts / hub.ts / gravelVsAsphaltCost.ts general "typical range" figures (all hedged, all now verified) and the two GravelVsAsphaltCost.tsx table cells (#1 above) contain dollar literals. The Cost Index page and `DrivewayCostTable` compute every dollar figure live from `src/metro/lib/pricing.ts` at render time and label unconfirmed metros "(estimated)" — nothing there is typed in by hand.
- **No "nationwide" claims, no DFW storefront/yard-ownership claims** elsewhere (grepped all content + pages), no fabricated testimonials or stats. "DFW yards" is used correctly as a third-party-market reference everywhere except the two spots fixed above.
- **CTA prefill params**: `?qty=&unit=` from `GuideCalculator.tsx` are correctly read by `OrderFlow.tsx`'s `usePrefillOptions` (which also accepts `zip`, `category`, `variant`), validated against the target metro's own config before use. Not a bug — flagging only because it was worth confirming end-to-end, since `MetroCategoryPage.tsx` itself doesn't pass these through as props; `OrderFlow` reads them from the URL directly.
- **Internal links**: every `Link to=` in `pages/guides/**` and `components/guides/**` resolves to a route in `src/App.tsx` (including the two guides that hardcode `/dallas-fort-worth/gravel-delivery` and `/long-island/gravel-delivery` instead of composing `CATEGORY_ROUTE_SUFFIX` — these resolve correctly since the suffix is `-delivery`, just stylistically inconsistent with `SpokeNav.tsx`'s pattern; not worth an edit).
- **Schema**: HowTo appears only on the 4 genuinely procedural spokes (`maintenance`, `installation-steps`, `gravel-driveway-drainage`, `weeds-and-erosion-control`) — enforced by an existing vitest assertion. FAQPage JSON-LD is generated from `content.faqs` by `GuidePageShell`/`GravelDrivewayCostIndexPage`, so it's structurally impossible for it to drift from the visible FAQs. Article schema has author/publisher/datePublished/dateModified everywhere; the Cost Index's `Dataset` schema follows Google's documented fields (name, description, url, creator, license, distribution, temporalCoverage, spatialCoverage, variableMeasured).
- **Cost Index data** (`costIndexData.ts`, generated, not hand-edited): all 22 row slugs match `dfwCatalog.ts` 1:1 (so the "MyGravelGuy delivered" column never silently blanks out); the flagged `concrete-sand` exception (doesn't clear the broker-delivered median at the 0.25 premium) is correctly surfaced with a row `note`, matching the caveat already documented in `dallasFortWorth.ts`'s header comment. DFW node prices are consistently yard-class median × 0.85 (verified on `57-limestone`: 64.29 × 0.85 = 54.65, matches `dfwCatalog.ts` exactly).

## Recommendations for the orchestrator / owner (not fixed — judgment calls)

1. **Possible cannibalization**: `best-gravel`, `crusher-run-vs-57-vs-flex-base`, and `57-vs-8-stone` share a lot of the same compaction/drainage facts and material recommendations (crusher run 85-95%, #57 70-80%, flex base ≈ crusher run appears near-verbatim in two of the three). Each targets a genuinely distinct query ("best gravel," "crusher run vs #57 vs flex base," "#57 vs #8"), so this is probably fine as intentional topical-silo coverage rather than true duplication, but if AI engines start citing only one of the three for all three queries, consider sharpening `best-gravel`'s angle toward "which material for which soil/situation" and pushing the raw compaction-percentage comparison exclusively onto `crusher-run-vs-57-vs-flex-base`.
2. **"Free delivery" framing**: beyond the truckload-minimums page (fixed above), double-check whether "free delivery" is used as deliberate marketing language anywhere else in the metro/checkout flow (outside this agent's ownership) — if the brand does use it intentionally there, the "included in every price" wording used elsewhere in the Hub is more conservative and probably the safer AEO claim (it's true even if a future zone/metro ever separates delivery into its own itemized fee).
3. **DFW hands-on-experience framing**: more broadly than the two fixed spots, several DFW-facing pages' `howWeKnow` lines lean on Eastern LM's Long Island experience to vouch for DFW material recommendations. That's honest (`dallas-fort-worth.ts` and `crusherRunVs57VsFlexBase.ts` already hedge this correctly — "DFW yards stock X," not "we stock X in DFW"), but worth a final human pass once a real DFW partner yard is signed, to update these lines to reference actual DFW fulfillment experience instead of extrapolated LI experience.
